\section{Introduction}
\label{sec:introduction}

Internet connectivity is an input into an increasingly large set of production processes. For software developers, the dependence is especially direct: source code can be written locally, but modern development also relies on remote repositories, package registries, code review, issue tracking, continuous integration, documentation, and communication with collaborators. A nationwide loss of connectivity therefore interrupts both the transmission of code and many complementary tasks required to coordinate and ship software.

This paper studies a sharp episode of lost connectivity: Bangladesh's nationwide Internet shutdown in July 2024. Cloudflare reported that mobile networks began disconnecting early on July 18 and that national traffic fell to near zero later that day. Fixed broadband began to return on July 23, initially for selected sectors, while mobile connectivity recovered later, on July 28 \citep{belson2024}. Internet Society Pulse records the national disruption as beginning on July 18 and lasting roughly five and a half days \citep{isoc2024}. The event offers an unusual setting in which a digitally intensive form of work can be observed at high frequency before, during, and after a near-complete national loss of Internet connectivity.

This paper makes three contributions. The first concerns the immediate disruption: a nationwide loss of connectivity produced an unusually large collapse in observable software-development activity relative to a synthetic counterfactual built from other countries. The second concerns adaptation: Git metadata distinguish online publication from local code creation and identify a small delayed-publication backlog alongside a roughly 96--97 percent fall in observable author-time commit creation. The third concerns persistence: the original synthetic series implies an 8,145 active-user-day shutdown deficit, followed by only a partial cumulative offset through September 4; restoring connectivity did not imply a uniform recovery, and observable activity returned at different speeds across the economic sectors associated with developers' repositories. The third contribution is descriptive heterogeneity within Bangladesh rather than a set of sector-specific causal effects.

The empirical challenge is that GitHub activity is volatile and highly heterogeneous across countries and developers. I therefore construct a multi-country donor pool and use synthetic control as the primary design. The treated unit is Bangladesh, and the donor pool contains fourteen countries with different sample sizes, including 1,373 eligible Ghana-associated accounts and 446 Jordan-associated accounts. Small-country rates may be noisy; minimum-size donor rules are reserved for advisor review. The synthetic-control weights are chosen using the pre-shutdown path of the daily active-user rate. The resulting counterfactual assigns 47.6 percent weight to Pakistan, 32.5 percent to Ghana, and 19.9 percent to Kenya. During July 18--23, the share of eligible Bangladeshi users with productive GitHub activity averaged only 2.02 percent, compared with 15.28 percent in the synthetic control. The estimated effect is $-$13.26 percentage points, or $-$86.8 percent relative to the synthetic counterfactual.

Several complementary designs support the same conclusion. An international difference-in-differences comparison yields an effect of $-$13.09 percentage points, and excluding national holidays changes the estimate only modestly to $-$13.38 percentage points. Outcome-specific synthetic controls show declines of 86.7 percent in productive activity, 90.5 percent in shipping activity, and 91.9 percent in collaborative activity. A regression discontinuity in time at the July 17 cutoff produces a smaller but still large discontinuity of roughly $-$9 percentage points in the daily activity rate.

The second contribution distinguishes observable online activity from underlying code creation. A Git commit can be created locally without Internet access, while the corresponding push to GitHub requires connectivity. For a large sample of public commits, I recover Git author and committer timestamps and match them to the first observed public PushEvent. In the strict sample where the commit author is the same GitHub account that performs the push, 829 of 2,932 commits authored during the July 18--23 shutdown, or 28.3 percent, are first observed in a public push on or after July 24. Using the committer timestamp yields 27.2 percent. The share of shutdown-authored commits delayed by more than 24 hours is 29.7 percent, compared with an average of 1.1 percent across six comparable pre-shutdown placebo windows of six days each. The level comparison is more restrictive: starting at 15:00 UTC July 18 leaves 1,097 commits, 96.35 percent below duration-matched pre-shutdown windows; the 752-commit backlog is only 2.50 percent of that normal volume. The six-day comparison gives a 96.75 percent decline and a 2.45 percent backlog-to-baseline ratio. These counts concern code pushed publicly by August 10, with unresolved metadata and later pushes unobserved.

The third contribution turns from the shutdown window to the restoration period. Using a fixed sample of 20,000 Bangladesh-associated accounts selected on pre-shutdown activity, and a text classifier that assigns repositories to NAICS sectors from historical README files, I trace observable push activity by the economic sector associated with the repositories in which it occurs. Restoration of connectivity did not imply an immediate or uniform recovery. Activity in Finance- and Information-related repositories began a two-week run at or above 80 percent of its pre-shutdown level by the third week after the shutdown; Education and Health recovered more gradually; and Accommodation/Food remained well below its baseline throughout the observed window. Activity in pre-existing repositories recovered far less than sector-wide activity, consistent with part of the recovery occurring through new projects. Because this analysis compares each sector with its own pre-shutdown level rather than with an untreated control, it describes heterogeneity in recovery dynamics and does not estimate sector-specific causal effects.

The findings relate to three literatures. First, they add micro-founded evidence to work on the economic costs of Internet shutdowns and, more broadly, of infrastructure outages. Existing studies document broad effects on output, employment, investment, and economic activity \citep*{tagat2024,gunsilius2023}, and \citet{allcott2016} show how firms cope when electricity becomes unavailable. Second, the paper contributes to research on Internet access as a productive input. \citet{hjort2019}, for example, find that the arrival of fast Internet increased employment and firm performance in Africa, and \citet{akerman2015} show that broadband complements skilled work. Third, the paper joins a growing literature that uses public GitHub activity as a high-frequency measure of software work. \citet{kreitmeir2024} exploit Italy's temporary ChatGPT ban and construct daily GitHub outcomes; \citet{hu2023} use open-source contributions to study lockdowns; and \citet{wachs2022} demonstrate the usefulness of GitHub data for measuring the geography of software production.

The interpretation is deliberately narrower than `total software productivity.' Public GitHub events omit private repositories, other hosting services, meetings, local coding that is never pushed publicly, and non-coding work. User location is self-reported rather than physically verified. Most importantly, the shutdown was implemented amid severe domestic unrest, so the design cannot mechanically separate every contemporaneous Bangladesh-specific shock from the connectivity shock. The paper therefore estimates a large collapse in observable GitHub software-production activity during the shutdown episode, and then uses the commit-timestamp mechanism to examine whether delayed connectivity is consistent with accounting for part of the observed collapse.
