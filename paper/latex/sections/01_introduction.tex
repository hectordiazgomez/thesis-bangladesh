\section{Introduction}
\label{sec:introduction}

Internet connectivity is an input into an increasingly large set of production processes. For software developers, the dependence is especially direct: source code can be written locally, but modern development also relies on remote repositories, package registries, code review, issue tracking, continuous integration, documentation, and communication with collaborators. A nationwide loss of connectivity therefore interrupts both the transmission of code and many complementary tasks required to coordinate and ship software.

This paper studies a sharp episode of lost connectivity: Bangladesh's nationwide Internet shutdown in July 2024. Cloudflare reported that mobile networks began disconnecting early on July 18 and that national traffic fell to near zero later that day. Fixed broadband began to return on July 23, initially for selected sectors, while mobile connectivity recovered later, on July 28 \citep{belson2024}. Internet Society Pulse records the national disruption as beginning on July 18 and lasting roughly five and a half days \citep{isoc2024}. The event offers an unusual setting in which a digitally intensive form of work can be observed at high frequency before, during, and after a near-complete national loss of Internet connectivity.

The empirical challenge is that GitHub activity is volatile and highly heterogeneous across countries and developers. I therefore construct a multi-country donor pool and use synthetic control as the primary design. The treated unit is Bangladesh, and the donor pool contains fourteen countries with sizable GitHub communities. The synthetic-control weights are chosen using the pre-shutdown path of the daily active-user rate. The resulting counterfactual assigns 47.6 percent weight to Pakistan, 32.5 percent to Ghana, and 19.9 percent to Kenya. During July 18--23, the share of eligible Bangladeshi users with productive GitHub activity averaged only 2.02 percent, compared with 15.28 percent in the synthetic control. The estimated effect is $-$13.26 percentage points, or $-$86.8 percent relative to the synthetic counterfactual.

Several complementary designs support the same conclusion. An international difference-in-differences comparison yields an effect of $-$13.09 percentage points, and excluding national holidays changes the estimate only modestly to $-$13.38 percentage points. Outcome-specific synthetic controls show declines of 86.2 percent in productive activity, 92.2 percent in shipping activity, and 92.1 percent in collaborative activity. A regression discontinuity in time at the July 17 cutoff produces a smaller but still large discontinuity of roughly $-$9 percentage points in the daily activity rate.

The paper's second contribution is to distinguish observable online activity from underlying code creation. A Git commit can be created locally without Internet access, while the corresponding push to GitHub requires connectivity. For a large sample of public commits, I recover Git author and committer timestamps and match them to the first observed public PushEvent. In the strict sample where the commit author is the same GitHub account that performs the push, 829 of 2,932 commits authored during the July 18--23 shutdown, or 28.3 percent, are first observed in a public push on or after July 24. Using the committer timestamp yields 27.2 percent. The share of shutdown-authored commits delayed by more than 24 hours is 29.7 percent, compared with an average of 1.1 percent across six comparable pre-shutdown placebo windows of six days each. These patterns are consistent with local code production continuing for some developers while publication and synchronization were deferred until connectivity returned.

The findings contribute to three literatures. First, they add micro-founded evidence to work on the economic costs of Internet shutdowns. Existing studies document broad effects on output, employment, investment, and economic activity \citep*{tagat2024,gunsilius2023}. Second, the paper contributes to research on Internet access as a productive input. \citet{hjort2019}, for example, find that the arrival of fast Internet increased employment and firm performance in Africa. Third, the paper joins a growing literature that uses public GitHub activity as a high-frequency measure of software work. \citet{kreitmeir2024} exploit Italy's temporary ChatGPT ban and construct daily GitHub outcomes; \citet{hu2023} use open-source contributions to study lockdowns; and \citet{wachs2022} demonstrate the usefulness of GitHub data for measuring the geography of software production.

The interpretation is deliberately narrower than `total software productivity.' Public GitHub events omit private repositories, other hosting services, meetings, local coding that is never pushed publicly, and non-coding work. User location is self-reported rather than physically verified. Most importantly, the shutdown was implemented amid severe domestic unrest, so the design cannot mechanically separate every contemporaneous Bangladesh-specific shock from the connectivity shock. The paper therefore estimates a large collapse in observable GitHub software-production activity during the shutdown episode, and then uses the commit-timestamp mechanism to examine whether delayed connectivity is consistent with accounting for part of the observed collapse.
