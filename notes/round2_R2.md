# R2 — definitions audit (partially blocked)

`analysis/round2/r2_definitions.py` verifies the any-event-day eligibility count exactly for all retained users. Four days in May 1–July 17 is the threshold; dates are UTC. It yields 60,729 candidates, including all 59,158 retained users, and exports membership for the 1,571 unexplained exclusions. No bot exclusion is reverse-engineered from the desired final count. The archived name_bot and behavior_bot flags are all false for retained users; regexes, thresholds and excluded-user flags are missing. This script reconstructs the verifiable candidate stage, not a falsely complete eligible_users_donors builder.

The exact productive_events type/action mapping is absent from the available code and cannot be inferred uniquely from aggregates. 104,786 / 1,103,680 active eligible user-days have none of the stored push/PR/issue/release/review/comment components. Section 4.2 and Table 2 now explicitly distinguish the primary stored indicator (pre-period Bangladesh 17.25454996%) and the verified secondary formula (commits + issues_closed + pr_closed + releases > 0; 15.37948267%). Neither series was changed.

Pending: original GH Archive aggregation SQL, bot-pattern list and thresholds, and excluded-account audit. `analysis/pending/r2_event_types.sql` provides the exact external query needed to recover event/action counts, not executed because the user forbids filling missing external data by assumption. Even matching event counts requires provenance from the original code before claiming the historical definition is known.

The three stored behavioral metrics are reconstructable for every one of the 59,158 retained accounts from May 1–July 17: max_daily_commits is the maximum daily commits count, commit_days counts dates with commits>0, and commit_day_share is commit_days/78 (calendar days, not pre_active_days). The script verifies all three exactly to numerical tolerance. These metric definitions do not identify the missing exclusion thresholds or justify assigning bot labels to the 1,571 excluded candidates.

Final cross-check: the independent sector event panel contains eight selected types (CommitCommentEvent, IssueCommentEvent, IssuesEvent, PullRequestEvent, PullRequestReviewCommentEvent, PullRequestReviewEvent, PushEvent, ReleaseEvent). Across 179,468 overlapping Bangladesh user-days, their count matrix has rank 8 and rank 9 after appending primary productive_events. Thus even an unrestricted linear combination of those stored event counts cannot exactly reconstruct the primary count. This independently rules out claiming that these eight types are its verified definition; the upstream mapping remains pending.
